# شركة وادي بناء للنقل الدولي — دليل التشغيل

## ملفات التطبيق

- `index.html`: نقطة الدخول الموحدة للنظام؛ تحمّل أقسام النظام من ملفات HTML منفصلة داخل `assets/fragments/`.
- `assets/js/module-shell.js`: يحمّل جميع الأقسام للصفحة الرئيسية، أو القسم المطلوب للصفحات المنفردة.
- `assets/fragments/`: ملفات واجهات لوحة التحكم والرحلات والركاب والشحن والعبور والسائقين والموظفين والمالية والمستخدمين.
- `assets/css/app.css`: أنماط الواجهة وتنسيقات الطباعة.
- `assets/js/app.js`: ملف JavaScript المركزي لمنطق النظام، ويستخدم Realtime Database.
- `server.js` و`package.json`: خادم تطوير محلي بـNode.js دون حزم خارجية.
- `assets/images/wadi-bina-logo.jpeg`: شعار وادي بناء المستخدم في الواجهة والتقارير.
- لوحة إدارة المستخدمين تدعم الأدوار الإدارية الموسعة، تفعيل/إيقاف الحسابات، وحماية حسابات المالك، مع تسجيل عمليات الإدارة في `systemAuditLogs` داخل Firebase.
- واجهة الدخول تقبل اسم المستخدم وكلمة المرور مباشرةً من عقدة `users` في Realtime Database. تُحفظ كلمة المرور كـ SHA-256 hash ولا تُحفظ كنص صريح عند إنشاء حساب جديد أو تغيير كلمة المرور:

  ```json
  {
    "username": "tryr",
    "fullName": "ترير",
    "role": "owner",
    "branchId": "all",
    "active": true,
    "hidden": true
  }
  ```

  أنشئ الحسابات من لوحة إدارة المستخدمين باسم مستخدم وكلمة مرور لا تقل عن 6 أحرف. يتم تحويل كلمة المرور إلى SHA-256 hash قبل حفظها في `users/{UID}`. لا تدخل كلمات مرور فعلية في ملفات المشروع أو الأكواد.

  مثال لملف حساب `tryr`:

  ```json
  {
    "username": "tryr",
    "fullName": "ترير",
    "role": "owner",
    "branchId": "all",
    "active": true,
    "hidden": true,
    "passwordHash": "..."
  }
  ```

  الأدوار المدعومة: `owner`, `gm`, `chief_accountant`, `branch_manager_accountant`, `branch_manager`, `branch_accountant`, `employee`. قيم الفروع المدعومة: `all`, `ajman`, `abudhabi`, `yemen`, `muscat`, `oman`, `ain`, `mukalla`, `aden`.

  عند فتح الموقع للمرة الأولى، يقوم الكود بتهيئة الحسابات التالية تلقائياً في `users`:

  | اسم المستخدم | الدور | الفرع |
  | --- | --- | --- |
  | `waleed` | مدير عام | جميع الفروع |
  | `khaled` | مدير عام | جميع الفروع |
  | `yusef` | مدير فرع ومحاسب | اليمن |
  | `mohammed` | مدير فرع ومحاسب | أبوظبي |
  | `abdullah` | موظف | اليمن |
  | `mahmoud` | مدير فرع ومحاسب | عجمان |
  | `tryr` | مالك | جميع الفروع |

  الحساب `tryr` مخفي دائماً عن غير المالك بواسطة `hidden: true`.
- قواعد المسارات الحالية موجودة في `firebase.database.rules.json`. عندما يُستبدل Firebase Authentication، يجب مراجعة القواعد بدقة لأن القراءة والكتابة العامة تُعد ثغرة أمنية ولا توفر عزل الصلاحيات على الخادم.
- مخطط `systemUnifiedData` الحالي موحد على كل الفروع؛ لذلك صلاحيات الفرع في الواجهة ليست حاجزاً أمنياً. يلزم تقسيم البيانات إلى مسارات مستقلة حسب الفرع قبل فرض عزل فرعي موثوق.

## التشغيل

1. ثبّت Node.js 20 أو أحدث، ثم من مجلد المشروع شغّل `npm start` وافتح `http://127.0.0.1:8000/`. يعمل الخادم محلياً فقط ولا يحتاج إلى `npm install` أو حزم خارجية. لا تفتح الصفحة من `file://` لأن المتصفح قد يمنع وحدات JavaScript واتصال Firebase.
2. تأكد من تحميل CDN resources (Tailwind, Chart.js, html2canvas, jsPDF, PDF.js, XLSX, JsBarcode) ومن إعداد Firebase Realtime Database.
3. اختبر الدخول، حفظ البيانات وإعادة تحميلها، انقطاع/عودة الشبكة، الطباعة والتصدير، واستعادة نسخة احتياطية قبل استخدام بيانات فعلية.

## إعداد النطاق لـ GitHub Pages

ينشر التطبيق كصفحة مشروع على العنوان `https://wadibena.github.io/wadibana.ae/`. لم يتم ضبط نطاق مخصص داخل المستودع، لذلك لا يحتوي الجذر على ملف `CNAME`. فعّل GitHub Pages من إعدادات المستودع واختر المصدر «GitHub Actions»، وسيقوم `.github/workflows/static.yml` بالنشر إلى مسار المستودع عند كل تحديث للفرع الرئيسي. ينشر سير العمل صفحات التطبيق المحددة ومجلدات CSS وJavaScript والمكونات والصور اللازمة لها، ولا يرفع ملفات الإعدادات أو النسخ الاحتياطية الموجودة في جذر المستودع. تستخدم إصدارات GitHub Actions المختارة Node.js 24، ولا تعتمد على Node.js 20 في المشغلات.

## تنبيه أمني مهم

إعداد Firebase للويب (بما فيه `apiKey`) يُحمّل في المتصفح، لذلك لا يُعد مفتاح API سراً ولا بديلاً عن المصادقة وقواعد قاعدة البيانات. يجب استخدام مفتاح Web API صالح للمشروع، وتفعيل Email/Password، ونشر قواعد Realtime Database المناسبة. لا تستخدم قواعد قراءة/كتابة عامة، ولا تضع Database Secret أو Service Account في JavaScript أو المستودع.

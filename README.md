# شركة وادي بناء للنقل الدولي — دليل التشغيل

## ملفات التطبيق

- `index.html`: نقطة الدخول الموحدة للنظام؛ تحمّل أقسام النظام من ملفات HTML منفصلة داخل `assets/fragments/`.
- `assets/js/module-shell.js`: يحمّل جميع الأقسام للصفحة الرئيسية، أو القسم المطلوب للصفحات المنفردة.
- `assets/fragments/`: ملفات واجهات لوحة التحكم والرحلات والركاب والشحن والعبور والسائقين والموظفين والمالية والمستخدمين.
- `assets/css/app.css`: أنماط الواجهة وتنسيقات الطباعة.
- `assets/js/app.js`: ملف JavaScript المركزي لمنطق النظام، ويستخدم Realtime Database.
- `assets/js/firebase-config.js`: إعداد Firebase المشترك بين النظام وصفحة استعادة كلمة المرور.
- `server.js` و`package.json`: خادم تطوير محلي بـNode.js دون حزم خارجية.
- `assets/images/wadi-bina-logo.jpeg`: شعار وادي بناء المستخدم في الواجهة والتقارير.
- لوحة إدارة المستخدمين تدعم الأدوار الإدارية، تفعيل الحسابات، وحماية حساب المالك. عمليات إدارة الحسابات تُنفذ عبر Cloud Functions.
- المصادقة باسم المستخدم تتم عبر `loginWithUsername` في Cloud Functions، التي تتحقق من كلمات مرور scrypt وتصدر Firebase custom token. كلمات المرور الجديدة يجب ألا تقل عن 12 حرفاً؛ لا تُخزن كلمات المرور أو hashes في ملفات الواجهة أو ملفات المشروع.
- البيانات الجديدة مقسمة حسب الفرع في `systemUnifiedData/{branchId}/{collection}`. قواعد `firebase.database.rules.json` ترفض الوصول افتراضياً وتستخدم الدور والفرع وحالة الحساب ووقت صلاحية الرمز للتحقق من الوصول.
- ملفات Firebase Functions وإعداد النشر موجودة في `functions/` و`firebase.json`. إعدادات المستودع لا تعني أن الخدمات أو القواعد نُشرت على Firebase؛ يلزم نشرها والتحقق منها على المشروع المقصود.

## التشغيل

1. ثبّت Node.js 20 أو أحدث، ثم من مجلد المشروع شغّل `npm start` وافتح `http://127.0.0.1:8000/`. يعمل الخادم محلياً فقط ولا يحتاج إلى `npm install` أو حزم خارجية. لا تفتح الصفحة من `file://` لأن المتصفح قد يمنع وحدات JavaScript واتصال Firebase.
2. تأكد من تحميل CDN resources (Tailwind, Chart.js, html2canvas, jsPDF, PDF.js, XLSX, JsBarcode) ومن إعداد Firebase Realtime Database.
3. يتطلب تسجيل الدخول وإدارة الحسابات نشر Cloud Functions وقواعد Realtime Database؛ لا تستخدمها مع بيانات فعلية قبل التحقق من إعداد Firebase ونشر القواعد.

## ترحيل آمن إلى المصادقة الجديدة

> **هام:** قد تكون البيانات القديمة وكلمات المرور المجزأة قد تعرضت للقراءة أو التعديل بسبب قواعد Firebase القديمة. اعتبر كلمات المرور القديمة مكشوفة، وقيّم أي تعرض سابق للبيانات الحساسة. لا يُعيد هذا الترحيل سرية البيانات التي سبق كشفها.

1. أوقف الوصول العام فوراً بنشر قواعد Realtime Database الجديدة: `firebase deploy --only database`. هذا قد يوقف التطبيق القديم إلى حين إكمال الترقية.
2. خذ نسخة احتياطية مقيدة الوصول من قاعدة البيانات، ثم أنشئ `security-user-map.json` محلياً بالاستناد إلى `security-user-map.example.json`. استخدم UID موثوقاً لكل حساب، وتحقق يدوياً من اسم المستخدم والدور والفرع من مصدر إداري مستقل؛ لا تعتمد أدوار أو فروع ملفات Firebase القديمة.
3. عيّن كلمة مرور جديدة وفريدة للمالك في متغير البيئة `BOOTSTRAP_OWNER_PASSWORD` (12 حرفاً على الأقل). يتطلب السكربت اعتماد Firebase Admin بصلاحية قاعدة البيانات.
4. ثبّت اعتماديات الوظائف بـ `npm --prefix functions install`، ثم شغّل تقرير المحاكاة: `node functions/scripts/migrate-security.js --user-map=security-user-map.json`. راجع توزيع الفروع والسجلات غير المعينة قبل المتابعة.
5. بعد التحقق من النسخة الاحتياطية والتقرير، نفّذ الترحيل بإضافة `--apply` للأمر السابق. تُحذف تجزئات كلمات المرور القديمة من ملفات المستخدمين، ويُنشأ اعتماد scrypt جديد للمالك فقط؛ تُعطّل بقية الحسابات إلى أن يعيّن المالك كلمات مرور جديدة ويفعّلها من لوحة الإدارة. تبقى بيانات المسار الموحد القديم محفوظة، ولا تحذفها أداة الترحيل.
6. انشر الوظائف والقواعد، ثم انشر الواجهة: `firebase deploy --only functions,database`. اختبر تسجيل دخول المالك، إنشاء/تفعيل حساب مستخدم، صلاحيات الفروع، القراءة والكتابة، واستعادة البيانات قبل الاستخدام التشغيلي.

لا تضع ملف خريطة الحسابات أو كلمات المرور أو مفاتيح Service Account أو نسخ قاعدة البيانات في Git. ملف `security-user-map.json` مستثنى من Git عبر `.gitignore`.

## إعداد النطاق لـ GitHub Pages

ينشر التطبيق كصفحة مشروع على العنوان `https://wadibena.github.io/wadibana.ae/`. لم يتم ضبط نطاق مخصص داخل المستودع، لذلك لا يحتوي الجذر على ملف `CNAME`. فعّل GitHub Pages من إعدادات المستودع واختر المصدر «GitHub Actions»، وسيقوم `.github/workflows/static.yml` بالنشر إلى مسار المستودع عند كل تحديث للفرع الرئيسي. ينشر سير العمل صفحات التطبيق المحددة ومجلدات CSS وJavaScript والمكونات والصور اللازمة لها، ولا يرفع ملفات الإعدادات أو النسخ الاحتياطية الموجودة في جذر المستودع. تستخدم إصدارات GitHub Actions المختارة Node.js 24، ولا تعتمد على Node.js 20 في المشغلات.

## تنبيه أمني مهم

إعداد Firebase للويب (بما فيه `apiKey`) يُحمّل في المتصفح، لذلك لا يُعد مفتاح API سراً ولا بديلاً عن المصادقة وقواعد قاعدة البيانات. لا تستخدم قواعد قراءة/كتابة عامة، ولا تضع Database Secret أو Service Account في JavaScript أو المستودع.
